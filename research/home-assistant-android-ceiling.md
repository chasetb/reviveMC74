# Home Assistant access and Android upgrade ceiling for the MC-74

Research for [issue #5](https://github.com/chasetb/reviveMC74/issues/5), checked 2026-11-16. This is a source review only: no device commands, installs, or flashes were run.

## Findings

| Question | Evidence and conclusion |
| --- | --- |
| What Android version does this project support? | The upstream project's README says Revive keeps the original Android 4.2.3 (Jelly Bean, API 17). Its objectives replace recovery, back up and patch the boot image, then install/remove apps; they do not install a replacement Android OS. Treat 4.2.3 as the project's evidenced platform, not a claim about the hardware's theoretical ceiling. [Project README](https://github.com/reviveMC74/reviveMC74#phone-software) [AOSP version/API table](https://source.android.com/docs/setup/reference/build-numbers) |
| Can the current Companion app run on that baseline? | No. Home Assistant's getting-started page lists Android 6+ (API 23) as the minimum. Stable Companion release 2026.11.1 says it is the last release to support Android 6; the 2026.11.2 pre-release drops API 23, so that pre-release's floor is Android 7 (API 24). Android 4.2.3 is API 17 and falls below both. The `minimal` flavor removes the Google Play Services requirement, but does not lower the OS minimum. [Requirements](https://companion.home-assistant.io/docs/getting_started/) [2026.11.1/2026.11.2 releases](https://github.com/home-assistant/android/releases) [Android flavors](https://companion.home-assistant.io/docs/core/android-flavors/) |
| Can the current Home Assistant web UI run in the stock browser? | There is no supported evidence that it can. Home Assistant 2026.11 sets floors of Chrome 67, Safari 15.4, or Firefox 98. The AOSP Android 4.2 compatibility definition specifies WebKit 534.30 for the platform WebView, not a modern Chromium WebView. This makes the stock 4.2-era browser an implausible match for the current frontend; the MC-74's actual standalone browser and WebView versions were not measured, so this is a platform-based inference, not a boot test. [Frontend requirements](https://www.home-assistant.io/blog/2026/11/04/release-202611/) [Android 4.2 WebView definition](https://source.android.com/docs/compatibility/4.2/android-4.2-cdd) |
| Is there a documented MC-74 Android upgrade? | I found no authenticated, reproducible MC-74 replacement build newer than 4.2.3. The current project describes modifying the boot image and apps while retaining Android 4.2.3. The PhoenixSheppy `/system` ZIP discussed in [issue #4](https://github.com/chasetb/reviveMC74/issues/4) was not authenticated or evidenced as MC-74-compatible; it cannot support an upgrade recommendation. Cisco's MC-74 datasheet documents display, network, audio, and power features but no Android version, SoC, memory, or OS-upgrade path. Do not infer a version ceiling from generic chipset support. [Project README](https://github.com/reviveMC74/reviveMC74#phone-software) [Cisco MC-74 datasheet](https://meraki.cisco.com/lib/pdf/meraki_datasheet_mc74.pdf) |

## Upgrade reports: evidence versus speculation

- **Project baseline:** the upstream README explicitly identifies Android 4.2.3/API 17 and only describes recovery/boot/app changes. The supplied issue #2 baseline also records CWM Recovery 6.0.4.7 reachable, ADB absent, no original boot/recovery/system backups, and Fastboot unverified. These are project/session records, not observations made during this research. [Project README](https://github.com/reviveMC74/reviveMC74#phone-software) [Issue #2](https://github.com/chasetb/reviveMC74/issues/2)
- **Modified stock Android, not a newer OS:** a 2019 MC-74 owner describes installing custom recovery, removing Meraki system apps, and adding a launcher/navigation bar to obtain a usable Jelly Bean environment. This is a first-person community report, not a verified artifact or current-device test. [MC-74 discovery/root thread](https://www.reddit.com/r/meraki/comments/c0lpvl/)
- **Unverified higher-version claim:** a separate 2019 thread says “from what I can tell” the device is running Android 4.4.2, but provides no build identity, image, repeatable installation record, or boot evidence. It is not credible upgrade support. [MC-74 ROM thread](https://www.reddit.com/r/meraki/comments/clt3cp/)
- **No hardware maximum established:** neither the project nor Cisco's datasheet substantiates an Android version above 4.2.3 for this exact device. The evidence ceiling is therefore 4.2.3; it does not prove the silicon could never run a newer build. No generic SoC-to-ROM compatibility inference is used here.

## Recommended first Home Assistant interaction

On the evidenced Android 4.2.3 platform, neither the current Companion app nor the current web frontend has a documented supported route. The smallest plausible first interaction is a purpose-built API 17 client that displays one Home Assistant entity state using `GET /api/states/<entity_id>`. Home Assistant documents this endpoint as a JSON state read and requires an `Authorization` token for API requests. This is an inference from the Android API level and Home Assistant's API contract; no such client exists in this repo and no MC-74 install or network test has proved it works. [Home Assistant REST API](https://developers.home-assistant.io/docs/api/rest/) [AOSP Android 4.2/API 17](https://source.android.com/docs/setup/reference/build-numbers)

Keep the first probe read-only and local. The REST API token is a real credential, and Android 4.2 is obsolete; do not send it over untrusted Wi-Fi or weaken certificate validation to make an old client connect. A successful HTTPS connection, certificate trust, a minimal credential strategy, and reliable APK delivery on this MC-74 remain unverified. If those cannot be made safe and repeatable, there is no presently evidenced HA interface for the stock OS.

## Decision

Use **Android 4.2.3/API 17** as the highest MC-74 Android version supported by evidence today. First pursue a single-state REST read in a minimal API 17 client on the existing platform, only after the map's original-backup and recovery gate is met. Treat Android 4.4.2, PhoenixSheppy ZIP compatibility, and any higher Android port as speculation until an identified build is authenticated and boot-tested on this exact hardware. Do not flash or install based on the available research.
