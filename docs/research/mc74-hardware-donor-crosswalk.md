# MC-74 hardware paths versus the GT-I9152 donor

**Status:** preliminary source-only crosswalk for Wayfinder issue #38. It is not a parity claim. The MC-74 system-HAL inventory in issue #36 remains a blocker, so this memo cannot establish a compatible image or close the hardware gate.

## Evidence boundary

MC-74 behavior below comes from the local primary-checkout file `rmcBootRamdisk/init.bcm911130_me1.rc` (line references shown per row). The path is ignored by Git (`.gitignore:7`) and is not included in this branch; the statements describe the available local boot/init configuration, not a public or complete source tree. The local script configures interfaces and starts services; it does not by itself identify every device part or prove a path works on a replacement build.

The public donor evidence is the GT-I9152 [`BoardConfig.mk`](https://github.com/ghsr/android_device_samsung_i9152/blob/cm-14.1/BoardConfig.mk), [`lineageos_i9152_defconfig`](https://github.com/ghsr/android_kernel_samsung_i9152/blob/android-7.1/arch/arm/configs/lineageos_i9152_defconfig), and [`proprietary-files.txt`](https://github.com/ghsr/android_device_samsung_i9152/blob/cm-14.1/proprietary-files.txt). They describe the Crater phone build, not the MC-74 board. MC-74 system-HAL evidence is unavailable in this worktree; issue #36 is blocked on issue #35, which stages the system partitions. No capture manifest or userdata was examined for this crosswalk.

## Decision

The donor offers useful same-SoC candidates for Wi-Fi, Bluetooth, sensors, audio, USB, and power management. It does not currently establish a path for every MC-74 behavior: touch differs, the MC-74 managed Ethernet switch utility has no donor counterpart identified, LP5521 is disabled, and the MC-74 display/backlight, charger, audio, and hook-switch integrations remain board-specific. Donor binaries cannot be treated as compatible until the missing MC-74 system partitions and their dependencies are inventoried.

**Source-only result:** do not proceed to a buildable full-parity specification on this evidence. Continue the inventory and seek a source, compatible-binary, or replacement path for each unresolved behavior. This is not proof that a port is impossible. No image was built, and no device test or write was performed.
